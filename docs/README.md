# OctoAcme Project Management Docs

## Purpose
Provide a central entry point to OctoAcme's project management documentation so new teammates can quickly understand the process and find the right guide.

## Overview
OctoAcme uses a lightweight but structured project lifecycle that moves from initiation through planning, execution, release, and retrospective improvement. Work starts with a clear business need, stakeholder alignment, success metrics, and a simple one-pager. Planning then turns the effort into a prioritized backlog, a release timeline, and a shared definition of done so teams can deliver in small, testable increments.

Delivery is cross-functional and built around clear ownership. Project Managers coordinate timelines, risks, dependencies, and communication. Product Managers define outcomes, prioritize work, and keep delivery aligned to customer and business value. Developers and QA contributors implement, test, review, and validate changes with support from stakeholders who provide approvals and feedback throughout the lifecycle.

Communication and quality assurance are part of the day-to-day workflow, not a final step. Teams use regular standups, weekly syncs, demos, stakeholder updates, and documented escalation paths to keep work visible and decisions clear. Quality practices include linked issues and acceptance criteria, small pull requests where possible, automated tests and linting in CI, security scanning, manual QA when needed, release readiness checks, and retrospectives that turn lessons learned into concrete improvements.
